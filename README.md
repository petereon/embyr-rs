# embyr-rs

A Rust reimplementation of the Google Firestore gRPC protocol server. It is a
**protocol translation layer** only — not a database; document data lives in
each customer's own Postgres.

## Workspace layout

5-crate Cargo workspace:

- `embyr-proto` — generated Firestore + agent gRPC stubs (no domain logic)
- `embyr-core` — pure domain types and port traits (no IO: no tokio, sqlx, tonic, axum)
- `embyr-server` — composition root; opens 3 TCP listeners (`:8080` gRPC, `:8081` REST/gRPC-Web/BrowserChannel, `:9090` Admin HTTP)
- `embyr-admin` — thin stub; the real admin HTTP server is the `:9090` listener inside `embyr-server`
- `embyr-agent` — customer-VPC agent binary (separate deployment, talks to the customer's own Postgres)
- `embyr-db-prep` — one-shot CLI that provisions/migrates a customer database before an agent connects
- `embyr-admin-ui` — Leptos SPA served by the admin HTTP surface
- `embyr-pg-storage` — Postgres storage adapter library (no env vars of its own)

## Configuration

embyr-rs has **3 binaries that each load their own configuration from
environment variables**: `embyr-server`, `embyr-agent`, and `embyr-db-prep`.
Each binary's config struct documents every variable it reads in its own
rustdoc:

- `crates/embyr-server/src/config.rs` — `ServerConfig`
- `crates/embyr-agent/src/config.rs` — `AgentConfig`
- `crates/embyr-db-prep/src/config.rs` — `DbPrepConfig`

**[`.env.example`](./.env.example) at the repo root is the single
cross-binary index** — every variable across all 3 binaries, grouped by
binary, with a one-line description, default (if any), and required/optional
status. It is generated by reading the config structs above; when you add or
change an env var, update the struct's rustdoc first (still the authoritative
per-field detail) and then add/update the matching line in `.env.example`.

To run a binary locally, copy `.env.example` to `.env`, fill in the values
for the binary you're running, and load it into your shell (e.g. `set -a;
source .env; set +a`) before `cargo run -p <crate>`. `.env` is gitignored —
never commit real secrets.
