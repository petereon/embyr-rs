## Feature Summary

embyr-rs is a complete Rust implementation of the Google Firestore gRPC wire protocol, acting as a **protocol translation layer** between Firebase SDKs and customer-owned PostgreSQL databases. It is not a database — it translates Firestore RPCs to SQL, performs auth, rate limiting, and real-time fan-out, then returns Firestore-shaped responses.

**5-crate Cargo workspace delivered:**
- `embyr-proto` — generated Firestore + agent gRPC stubs (no domain logic)
- `embyr-core` — pure domain types and port traits (zero IO imports; enforced by `deny.toml`)
- `embyr-server` — composition root, wires adapters, opens 3 TCP listeners (:8080 gRPC, :8081 REST/gRPC-Web/BrowserChannel, :9090 Admin HTTP)
- `embyr-admin` — admin HTTP server binary
- `embyr-agent` — customer-VPC agent binary (statically linked, mTLS gRPC)

## Key Decisions

Extracted from `docs/feature/embyr-rs/design/wave-decisions.md`:

| ID | Decision | Rationale |
|----|----------|-----------|
| AD-01 | 5-crate Cargo workspace | Enforces dependency hierarchy via Cargo resolver, not convention |
| AD-02 | `BackendAdapter` trait in `embyr-core` | Prevents upward dependency; domain functions write against trait, not adapter |
| AD-03 | Auth middleware per-request; credential cache stores resolved adapter | Clean separation of auth (middleware) and dispatch (cache hit → adapter) |
| AD-04 | `axum` for REST and admin ports | Tower-compatible; shares middleware stack with Tonic |
| AD-05 | `sqlx` with compile-time query checks | Catches query errors at compile time; no ORM abstraction for JSONB ops |
| AD-06 | `cargo-deny` + proc-macro + CI behavioral tests for boundary enforcement | Three orthogonal layers: compile-time, pre-commit AST, runtime CI test |
| AD-07 | `tracing` over `log` | Spans + async context propagation for distributed request tracing |
| AD-08 | Dedicated Postgres connection per project for NOTIFY | Prevents pool contention; LISTEN requires a dedicated connection lifecycle |
| AD-09 | BrowserChannel handler in `embyr-server::rest` | Same crate as gRPC handler; shares auth middleware and port binding |
| AD-10 | `google-cloud-secretmanager` community crate with `reqwest` fallback | Acceptable crate maturity; fallback design documented for OQ-01 |
| ADR-003 | Tokio multi-thread scheduler + `spawn_blocking` for Argon2id | Prevents Argon2id (64 MiB/op) from blocking async executor threads |
| ADR-004 | `tonic` 0.12.x + `tonic-web` + Axum for REST | Consistent Tonic version for both gRPC and gRPC-Web |

**Security invariants (locked, never change):**
1. ECIES private key derived from API token per-request — never stored
2. Argon2id params: memory=65536 KiB, iter=3, par=4 (64 MiB RAM per verification)
3. BLAKE3 cache keys: `(project_id, blake3(api_key))` — raw token never in cache
4. `backend_pg_creds_enc` NULL for agent-mode projects — enforced in provision handler
5. Per-project rate limit buckets isolated in `HashMap<String, TokenBucket>` — one project cannot starve another

**Open questions resolved during DELIVER:**

| OQ | Resolution |
|----|-----------|
| OQ-01 (GCP crate stability) | Used `reqwest` HTTP fallback via in-process GCP mock; community crate tested with emulator in CI |
| OQ-02 (gRPC-Web CORS) | `tonic-web` handles CORS natively; no edge cases encountered |
| OQ-03 (BrowserChannel protocol) | Implemented RPC-over-HTTP2 framing compatible with Firebase JS SDK |
| OQ-04 (NOTIFY channel name length) | Confirmed: `dc_<BLAKE3_16hex(project_id)>` = 19 chars, well within 63-char Postgres limit |
| OQ-05 (Argon2id cold-start) | Documented: first request ~200–500 ms; warm path uses credential cache |
| OQ-06 (Firestore conformance) | Acceptance tests derived from Firebase SDK integration test patterns; no public conformance suite |

## Lessons Learned

1. **Argon2id + concurrent tests = OOM**: Argon2id at `memory=65536` is 64 MiB per verification. 500 concurrent test requests = 32 GiB RAM required → machine freeze. Fix: `#[serial]` on all acceptance tests + warm-up block in each test to prime credential cache before burst.

2. **HTTP/2 multiplexing for concurrent gRPC tests**: Single `tonic::transport::Channel` clone across all concurrent tasks shares one TCP connection (HTTP/2 streams). Without this, each task creates a new channel; under load, TCP backlog prevents requests from reaching the rate-limiter at all.

3. **Token bucket warm-up math**: Capacity=10 + 1 warm-up request = 10 available before burst. Design burst tests with capacity = expected_allowed + warm-up_requests.

4. **Equivalent mutations in crypto length guards**: `replace + with -` on `32 + 12 + 16` produces thresholds 28 and 36 — both still protective. AES-GCM authentication catches invalid ciphertexts regardless of threshold. These are true equivalent mutants, not test gaps.

5. **NOTIFY channel name length**: Firestore project IDs can be 63 chars; `doc_changes_` prefix = 75 chars total, exceeding Postgres 63-char limit. Solution: `dc_<BLAKE3_16hex(project_id)>` = 19 chars.

6. **DES hook `TDD_PHASES` requirement**: Non-delivery tasks (refactoring, docs) must use `<!-- DES-ENFORCEMENT : exempt -->`, not `<!-- DES-VALIDATION : required -->` — the latter triggers mandatory TDD_PHASES section validation.
