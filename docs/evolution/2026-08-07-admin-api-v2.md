# Evolution Document — admin-api-v2

**Date:** 2026-08-07
**Feature ID:** `admin-api-v2`
**Waves:** DISCUSS → DESIGN → DISTILL → DELIVER
**Status:** Complete

---

## Feature Summary

admin-api-v2 is the backend DELIVER wave that wired 22 new Axum HTTP routes on the admin port (:9090) of embyr-rs. It replaced the mock data layer in the user-admin-ui (Slice 07) with real Postgres-backed endpoints, covering the full account administration surface: session authentication, project management, SDK key lifecycle, team membership, service accounts, OIDC SSO providers, billing aggregates, and diagnostic query logs.

**Business context:** The user-admin-ui Slices 01–06 (Leptos SPA) were completed with all UI components wired to mock data. admin-api-v2 is the backend that makes that console real. From the perspective of Chris (P5 — Account Admin), the dashboard now shows their actual databases, and their team can sign in, manage keys, and review usage without raw API calls.

**Scope:**
- 22 new HTTP routes across 6 backend slices (B-01 through B-06)
- 10 new Postgres tables + 2 schema alterations to `projects`
- 2 new adapters (`PostgresQueryLogAdapter`, `NoopEmailSender`)
- 1 new `embyr-core::admin` sub-module (port traits + pure domain types)
- 6 new ADRs (ADR-009 through ADR-014)
- 77 acceptance tests across 7 test files (1 walking skeleton + 6 focused suites)
- 23 delivery steps executed over 2 days (2026-08-05 → 2026-08-07)

## Architecture Decisions

These decisions are documented in full ADRs at `docs/product/architecture/` and copied to `docs/adrs/`.

| ID | Decision | ADR | Rationale |
|----|----------|-----|-----------|
| AA-01 | Sub-router merge with per-sub-router Tower layers for auth separation | ADR-009 | Four Axum routers built independently (operator, session, public, dual-auth) then merged; structural isolation prevents middleware cross-contamination between operator Bearer and session cookie stacks |
| AA-02 | `SessionContext` as Axum `FromRequestParts` extractor | ADR-010 | Compiler enforces presence; handler without `SessionContext` in its signature cannot access `account_id`, making cross-account data leaks a compile-time error rather than a runtime risk |
| AA-03 | `IEmailSender` driven port in `embyr-core::admin::email` | ADR-011 | Port traits belong in the inner hexagon; V1 `NoopEmailSender` trivially passes; V2 `SmtpEmailSender` adds real SMTP probe without changing the port contract |
| AA-04 | RBAC via pure domain function `check_rbac` | ADR-012 | Last-Owner invariant, self-demotion block, and key role cap require domain logic; pure function is testable without Axum or Postgres |
| AA-05 | Fire-and-forget `tokio::spawn` for query log writes; `IQueryLogWriter` port | ADR-013 | Zero client latency impact on gRPC handlers; bounded channel (1000) prevents unbounded task accumulation; consistent with `MetricsPort` pattern |
| AA-06 | `new_sdk_key_material` domain function; `backend_pg_dsn_enc` for DSN re-encryption | ADR-014 | No ECIES duplication; SDK keys go through the canonical `RotateAuthKey` aggregate command; `backend_pg_dsn_enc` (AES-256-GCM) resolves the old-key-unavailable problem for projects patching their DSN |
| AA-07 | New `embyr-core::admin` sub-module for admin domain types and ports | — | Admin domain vocabulary (Account, User, Session, Role, RBAC) belongs in core alongside existing BC-1/BC-2 modules |
| AA-08 | `UserAdminState` separate from `OperatorState`; both `with_state()`-erased before merge | — | Different dependency graphs: `UserAdminState` needs `email_sender` and `encryption_key`; `OperatorState` needs cloud secret fetchers; merging would require all handlers to carry the full dependency set |
| AA-09 | `QueryLogSweeper` Tokio task for partition pruning via `DROP TABLE` + advisory lock | — | `DROP TABLE` on old daily partitions is instant and lock-free vs. expensive `DELETE` sweeps; advisory lock prevents duplicate drops across multi-instance deployments |
| AA-10 | `SessionCleaner` Tokio task for expired session and invitation pruning | — | Hourly cleanup prevents unbounded `sessions` table growth; advisory lock pattern matches `QueryLogSweeper` |

**DISCUSS locked decisions carried into implementation:**

| # | Decision |
|---|----------|
| D1 | Session cookie auth: HTTP-only, BLAKE3 token hash, 24h idle expiry |
| D2 | Same port (:9090), route-level auth tagging via sub-router merge |
| D3 | `projects.account_id` FK as sole account-scoping mechanism; enforced in handler SQL |
| D4 | SDK keys go through `RotateAuthKey` aggregate command — no ECIES bypass |
| D5 | `query_logs` partitioned by day; old partitions dropped by background sweeper |
| D6 | Admin API keys as alternative to session cookie for the same user-facing routes |
| D7 | `GET /admin/v1/projects/:id` response shape expanded in-place — non-breaking |

## Lessons Learned

1. **Walking skeleton as middleware collision detector:** The B-01 walking skeleton was scoped to the narrowest possible journey (sign in → list projects → sign out) specifically because the biggest uncertainty was whether the two auth stacks would collide on :9090. This proved the sub-router merge (ADR-009) before any feature routes were built, and gave accurate early signal on the `async_trait` requirement for `session_auth_middleware` (step 01-03 E0195 fix).

2. **Pure domain functions in embyr-core are the easiest to test:** `check_rbac` (B-05) and `new_sdk_key_material` (B-03) are pure functions with no IO dependencies. They received proper unit test RED/GREEN cycles whereas handler tests had to use the acceptance tier. Placing non-trivial invariants (last-Owner block, ECIES derivation) in pure domain functions made the mutation testing results definitive.

3. **`spawn_blocking` is mandatory for Argon2id on the async executor:** Step 03-02 confirmed that SDK key creation must use `tokio::task::spawn_blocking` for the Argon2id hashing step. Not noted as a risk in DESIGN wave — adding this to the platform design checklist for any future handler that uses CPU-intensive crypto.

4. **DES phase skips on infrastructure steps are unavoidable:** 14 of 23 steps had SKIPPED RED phases. All were infrastructure steps (Tower middleware, SQL handler wired to DB, schema-only migrations) where there is genuinely no pure unit testable surface. The pattern to follow is: skip RED on infrastructure steps, accept acceptance tests as the integration gate, and ensure domain logic is extracted to embyr-core where RED/GREEN cycles are tractable.

5. **`backend_pg_dsn_enc` column resolves an otherwise invisible legacy problem:** OQ-B01 (pre-existing projects missing `backend_pg_dsn_enc`) was resolved by the DISTILL wave before implementation began. Without the explicit acceptance test `pre_existing_project_with_null_dsn_enc_skips_re_encryption_silently`, this edge case would have been discovered by a production failure when patching a legacy project.

6. **Adversarial review CONDITIONAL PASS is actionable:** The reviewer's findings (audit logging deferral DT-07, session index DDL DT-08, dual-auth isolation tests DT-09) were all addressed before DELIVER started. The two explicit middleware isolation tests added to B-02 (`operator_bearer_route_must_reject_session_cookie_auth`, `session_auth_route_must_reject_bare_bearer_token`) caught the exact class of bug they were designed to catch.

## Issues Encountered

### DES Phase Skips

Multiple steps had `NOT_APPLICABLE` phase skips on RED phases. All were justified:

- Steps 01-01 (SQL migrations), 01-02 (router refactor), 01-03 (Tower middleware), 01-04 (handler integrating DB + crypto): no pure unit testable surface; acceptance tests in 01-05 provide the integration gate.
- Steps 02-01, 02-02, 03-02, 04-01 through 04-03, 05-02, 05-03, 06-01 through 06-03: HTTP handlers that integrate DB; tested via slice acceptance suites (02-03, 03-03, 04-04, 05-04, 06-04 respectively).

No phase skips were unwarranted. All had explicit `NOT_APPLICABLE` justifications in `execution-log.json`.

### Interrupted Agent (Step 01-03)

Step 01-03 PREPARE was logged as SKIPPED because middleware and extractor scaffolding existed from a previous interrupted agent session. The E0195 compile error (missing `async_trait` on the `FromRequestParts` impl) was fixed in GREEN rather than written fresh. No functional difference — `cargo check` was used as the GREEN gate.

### Reviewer Findings Addressed Pre-DELIVER

| Finding | Severity | Resolution |
|---------|----------|------------|
| Audit logging not covered by ACs | High | Deferred (DT-07) — `tracing` spans on all handlers provide structured log entries sufficient for initial review |
| `sessions.token_hash` index missing from migration | Low | Added `CREATE UNIQUE INDEX sessions_token_hash_idx ON sessions(token_hash)` to B-01 migration (DT-08) |
| No explicit middleware collision acceptance tests | Critical | Two tests added to B-02 suite (DT-09) |

### Mutant Gaps

No gaps. The 100% kill rate on `embyr-core/src/admin/` domain files (`rbac.rs`, `account.rs`, `session.rs`, `email.rs`, `query_log.rs`) was achieved with the proptest for the sole-Owner invariant providing the coverage needed for the boolean-logic mutations in `check_rbac`.
